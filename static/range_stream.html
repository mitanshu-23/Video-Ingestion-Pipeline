Video Ingestion · Range Stream Viewer

Drive the POST /video/rangereq/stream/v1 flow. First the init request reports the total size and whether the file accepts ranges; then the player pulls the file in Range: bytes=start-end windows, each answered with 206 Partial Content, and stitches them back into a playable video. Prefer whole-file fetch? Go to the basic Stream Viewer →

Leave blank when this page is served by the axum server itself. Keep http://localhost:3000 if you open this file standalone. Cross-origin, the browser only lets JS read Content-Length, Content-Range and Accept-Ranges when the server lists them in Access-Control-Expose-Headers.

Sent as the uploadType query param. chunk/resumable resolve to their final_data sub-folder server-side.

Sent as the fileName query param. Range streaming only makes sense for video files.

1 · Init request — probe size & range support

POST {base}/video/rangereq/init/stream/v1?fileName=…&uploadType=… with no body. The server replies 200 OK carrying Content-Type, X-Content-Length (the file size — a custom header, since the tiny "OK" body owns the real Content-Length) and Accept-Ranges: bytes — everything the player needs to plan its range windows.

3 · Stream via ranges & play — assemble & render

      

        Loops Range windows across the whole file (using the length from step 1), collects every
        206 body in order, concatenates them into one Blob, and plays it. Works with a plain
        (non-fragmented) MP4 because the full file is reassembled client-side before playback.
